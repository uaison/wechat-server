## 克隆 uaison/wechat-server 仓库

**任务**：克隆 `https://github.com/uaison/wechat-server.git` 到 `D:/workspace/uaison-code/wechat-server`。

**结果**：已克隆成功，但**仓库是空的（size=0，无任何 commit）**，只生成了 `.git` 目录，`main` 分支尚无提交。

### 关键排查经验（重要，环境相关）

**现象**：直接 `git clone https://...` 报 `CONNECT tunnel failed, response 502`。

**根因**：环境注入了代理变量 `HTTP_PROXY/HTTPS_PROXY=http://127.0.0.1:54177`，
该代理**不认 CONNECT 隧道**，502 是代理层返回的，不是 GitHub 拒绝。用 `-c http.proxy=...`
显式指定或继承环境变量都会踩这个坑。`git://` 协议（9418）也被封。

**解决方案**：用 GitHub CLI 克隆，并**清空代理环境变量**：

```bash
cd <目标目录>
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy \
  "/c/Program Files/GitHub CLI/gh.exe" repo clone uaison/wechat-server .
```

### 本机环境事实（可复用）

- **GitHub CLI 已安装**：`C:\Program Files\GitHub CLI\gh.exe`（v2.102.0），但**未加入 PATH**，
  必须用绝对路径调用。
- **gh 已登录**：账号 `uaison`（凭据存 keyring），token scopes：`gist, read:org, repo, workflow`。
- git 全局配置里有 GitHub 凭据助手：
  `credential.https://github.com.helper=!'C:\Program Files\GitHub CLI\gh.exe' auth git-credential`
- 访问 `api.github.com` 正常；出问题的是经过本地代理的 `github.com` HTTPS。

## 搭建微信服务端 API 应用（技术栈确认 + 骨架落地）

**需求**：独立后端服务，对接微信公众号/小程序服务端接口，处理消息推送与 API 调用，
统一管理 access_token，业务数据落 MySQL。

**已确认的技术决策**（用户逐条确认）：

| 决策点 | 结论 |
|---|---|
| 语言/运行时 | Node.js 22（ESM） |
| Web 框架 | Koa 2（原因是验签需要**原始请求体**，Koa 中间件可控） |
| 数据库层 | Knex + mysql2（不用 ORM，SQL 可控） |
| token 获取接口 | `/cgi-bin/stable_token`（**不是**普通 `/cgi-bin/token`） |
| 常规刷新 force_refresh | `false`；仅在捕获凭据错误兜底时传 `true` |
| 取 token 策略 | 优先复用；剩余有效期 > 5 分钟才复用，否则刷新 |
| 兜底重试 | 捕获 40001/40014/42001 → 强制刷新 → **只重试一次** |
| 多号配置存储 | 全部入库（`wechat_accounts`），敏感字段**加密存储** |
| 部署形态 | 单机单实例（个人开发，一台腾讯云） |

**产出**：完整可运行骨架，20 个源文件，分 9 个模块（config/db/middleware/models/routes/services/scheduler/utils）。

**关键设计**：
- `src/services/token.service.js` 是核心：并发刷新用「进行中 Promise 合并」防打爆接口；
  `withToken(appid, fn)` 包装器让业务方无感处理 token 与重试。
- 敏感字段 AES-256-GCM 加密（带 `v1:` 版本前缀，含 authTag 防篡改），密钥只在 `.env`。
- 微信消息加解密严格按 WXBizMsgCrypt 规范实现（AES-256-CBC，PKCS7 块大小 32，明文含 random+len+msg+appid）。
- 回调路径出错时不向上抛 5xx（改为返回 success），防止微信疯狂重试。
- 消息处理用注册表模式（`register('event.subscribe', ...)`），新增类型不改分发逻辑。

**验证情况**：
- 语法检查 20 个文件全过。
- 自测 22 项全过（加解密往返、篡改检测、签名算法、消息加解密、appid 串号防护）。
- 集成测试 49 项全过（用 better-sqlite3 内存库替代 MySQL）：多账号隔离、
  token 复用时间边界（5 分钟边际）、凭据错误判定、验签完整链路、消息分发、API 路由。
- 启动冒烟：无 MySQL 时给出清晰中文错误并退出（早失败设计生效）。
- ⚠️ **本机无 MySQL、无 Docker**，真正的 MySQL 连库端到端测试未做，需在服务器上验证。

**待办**：项目尚未初始化 git commit；`.env` 里的 ENCRYPT_KEY 是临时生成值，正式部署需重新生成并备份。

## 实现多项目密钥管理（2026-10-17）

**背景**：用户确认此项目将作为**公共微信服务端**，后续多个项目共用 → 单一共享密钥不够
（无法隔离、无法单独吊销、无法审计）。对比「全局密钥 / 每项目独立密钥 / JWT」三方案后，
选定**每项目独立密钥 + appid 级授权**（JWT 的机器对机器场景下刷新成本高、吊销难，不值）。

**实现**（已全部完成并测试）：
- `migrations/20261017_01_api_clients.js`：api_clients 表（key_hash 只存 SHA-256、
  key_prefix 供识别、allowed_appids JSON 数组、enabled 吊销开关）
- `src/models/api-client.model.js`：create（明文仅返回一次）/ findEnabledByKey /
  update / setEnabled / rotateKey / canAccessAppid（支持 `["*"]` 通配）
- `src/middleware/auth.js`：apiAuth（X-API-Key/Bearer，校验启用状态 + appid 授权）、
  adminAuth（X-Admin-Key，保护 /api/clients；未配置 ADMIN_KEY 时返回 503 防裸奔）
- `src/routes/clients.js`：GET/POST/PATCH /api/clients、disable/enable/rotate
- `src/routes/api.js`：health 公开，其余全部 `apiRouter.use(apiAuth())`
- `src/db/knex.js`：支持 `DB_CLIENT=sqlite` 切内存库（测试基建）

**踩坑记录（重要经验）**：
1. **@koa/router 的 use() 中间件里 ctx.params 是空的**（实测确认），参数到路由处理器
   阶段才赋值 → apiAuth 必须用正则从 ctx.path 提取 appid，不能依赖 ctx.params。
2. **router.use() 只对其后注册的路由生效** → health 必须先注册，再 use(apiAuth())。
3. **raw-body 原来只读 POST/PUT**，PATCH 的 JSON body 读不到 → 已补 PATCH/DELETE。
4. ESM 静态 import 提升：测试里 process.env 赋值必须放在动态 import() 之前才有效。

**测试**：scripts/auth-test.js 33 项（真实模型层+真实中间件+HTTP 链路）：
签发格式、401/403 路径、appid 隔离（路径参数+请求体）、吊销即时生效、
轮换旧密钥失效、通配授权、ADMIN_KEY 与业务密钥互相隔离。
全量回归 22+50+33 = 105 项全过。

**文档**：API.md 增「密钥管理(管理员)」章节与鉴权约定；DEPLOYMENT.md 增 ADMIN_KEY
配置与首次签发流程；README 增两分钟理解；examples/client.js 增 clients/
create-client/disable-client/rotate-client 四个命令。
